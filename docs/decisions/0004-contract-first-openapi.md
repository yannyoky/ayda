# 0004. Contract-first OpenAPI

## Context
ADR 0002 made the OpenAPI schema generated by FastAPI the source of truth. The owner wants the Mini App and the backend built in parallel, which needs a stable contract before backend endpoints exist. A generated schema only appears after the code is written, and FastAPI's output drifts with refactors that nobody reviewed as API changes.

## Decision
`contracts/openapi.yaml` is a hand-written OpenAPI 3.1 file and the source of truth for the API. It is linted in CI with Redocly CLI (`recommended` rules). Clients (TypeScript for the Mini App, Kotlin later) are generated from this file. The backend implements it with FastAPI and Pydantic models that mirror its schemas; once endpoints exist, a backend test compares the schema FastAPI generates with the contract (paths, methods, status codes, request and response schemas) and fails on any difference. Errors follow RFC 9457 problem details; lists use opaque cursors.

This replaces the "Contracts" line of ADR 0002; the rest of ADR 0002 stands.

## Consequences
Frontend work can start from the contract and a mock server right away. Every API change is visible as a diff of one file and reviewed as such. Backend developers maintain Pydantic models by hand alongside the contract, and the conformance test is the guard against drift.
