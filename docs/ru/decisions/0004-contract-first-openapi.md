# 0004. Contract-first OpenAPI

[English](../../decisions/0004-contract-first-openapi.md) · Русский

## Контекст
ADR 0002 сделал источником истины OpenAPI-схему, которую генерирует FastAPI. Владелец хочет разрабатывать Mini App и бэкенд параллельно, а для этого нужен стабильный контракт ещё до появления эндпоинтов на бэкенде. Сгенерированная схема появляется только после написания кода, а вывод FastAPI плывёт при рефакторингах, которые никто не ревьюил как изменения API.

## Решение
`contracts/openapi.yaml` - написанный вручную файл OpenAPI 3.1 и источник истины для API. В CI он проверяется линтером Redocly CLI (правила `recommended`). Клиенты (TypeScript для Mini App, позже Kotlin) генерируются из этого файла. Бэкенд реализует его на FastAPI с Pydantic-моделями, повторяющими его схемы; когда появятся эндпоинты, тест бэкенда сравнивает схему, которую генерирует FastAPI, с контрактом (пути, методы, коды ответов, схемы запросов и ответов) и падает при любом расхождении. Ошибки возвращаются в формате problem details по RFC 9457; списки используют непрозрачные курсоры.

Это заменяет пункт «Контракты» в ADR 0002; остальное в ADR 0002 остаётся в силе.

## Последствия
Фронтенд можно начинать сразу по контракту и mock-серверу. Любое изменение API видно как diff одного файла и ревьюится как таковое. Бэкенд-разработчики вручную поддерживают Pydantic-модели вместе с контрактом, а тест соответствия защищает от расхождений.
