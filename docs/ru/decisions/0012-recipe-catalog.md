# 0012. Собственный курируемый каталог рецептов

[English](../../decisions/0012-recipe-catalog.md) · Русский

## Контекст
Квесту готовки M5 (#125) нужны рецепты с точными ингредиентами: приложение спрашивает, что есть дома, строит список покупок для части «купить продукты» (ADR 0010) и не должно пропускать аллерген. Сравнение - в `docs/recipe-sources.md` (issue #122). Нет открытого источника, который был бы русским, структурированным и с ясной лицензией: сайты рецептов защищены и их нельзя парсить, открытые наборы английские, неструктурированные или некоммерческие.

## Решение
- Рецепты - это **каталог, написанный для Ayda**, он лежит в репозитории по одному YAML-файлу на рецепт рядом с общим `ingredients.yaml`, проверяется JSON-схемой в тестах и загружается в базу модулем `assistant`. Шаги написаны своими словами. В начале около 40 обычных рецептов, которые владелец просматривает до выпуска.
- У ингредиента есть id, русское название с формами, единица, отдел магазина, аллергены и признак `staple`; рецепт перечисляет `{ingredient, amount, optional}`. Аллергены берутся только из ингредиентов.
- **Код** фильтрует рецепты (приём пищи, время, теги, исключённые ингредиенты и аллергены), пересчитывает количества на число людей, строит чек-лист «что есть дома» и список покупок. **LLM** только выбирает 2-3 id рецептов из кандидатов и формулирует предложение; её ответ проверяется по JSON-схеме и может содержать только id из кандидатов.
- Приложение показывает аллергены в рецепте и убирает рецепты с аллергеном, который назвал пользователь; оно никогда не говорит, что блюдо безопасно.

## Последствия
Лицензия чистая, а передача покупок не требует разбора текста. Разнообразие растёт вместе с работой по написанию рецептов, поэтому первый выпуск небольшой. Позднее пользовательские рецепты и Open Food Facts для фасованных продуктов ложатся в ту же схему. Фиксация списков единиц и отделов - часть #125.
