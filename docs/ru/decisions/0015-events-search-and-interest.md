# 0015. Поиск афиши в чате и сортировка по интересу

[English](../../decisions/0015-events-search-and-interest.md) · Русский

## Контекст
С M3 (ADR 0008) воркер загружает события на ближайшие 3 дня: для городов пользователей и крупнейшего города каждого их региона. В пул попадают до 2 событий в случайном порядке. Владелец (2026-10-23) хочет двух вещей. Во-первых, помощник должен искать афишу по запросу: по умолчанию в городе пользователя и по всей области, чтобы житель Калининграда видел и остальную Калининградскую область. Во-вторых, результаты нужно сортировать по интересу, а чек-ин должен приводить в пул подходящие ему события.

## Решение
- **Загрузка по всей области.** Для каждого региона, где есть пользователи, ночная задача `events.ingest` загружает города пользователей и 15 крупнейших по населению городов региона (`REGION_TOWNS`). Окно растёт с 3 до 7 дней, чтобы отвечать про «эти выходные» и «следующую неделю». Источники остаются прежними, Timepad и KudaGo, без парсинга сайтов. Областной портал добавляется только через открытый API или ленту, как новый источник.
- **Действие в чате.** ADR 0013 получает `find_events` с необязательными `query` (до 60 символов), `place` (город), `when` (`today`, `tomorrow`, `weekend`, `week`) и `category`. Без LLM код узнаёт запросы про афишу, концерты, выставки, театр и т. п. по ключевым словам, а город («в Светлогорске») и день берёт из текста. Карточку строит код: до 5 событий, по одному на название, со временем, местом, городом, расстоянием, ценой и ссылкой, плюс подпись «Афиша: Timepad и KudaGo».
- **Где искать.** По умолчанию поиск идёт по всему региону пользователя. Названный город того же региона сужает поиск до этого города. Для города из другого региона карточка говорит, что афиша собирается только по области пользователя. Неизвестный город заменяется регионом пользователя.
- **Интерес считает код.** Оценка кандидата складывается из:
  - слов запроса (совпадение основ в названии) ×3;
  - слов чек-ина ×1, не больше 3;
  - запрошенной категории +2;
  - категории, совпадающей с целями пользователя, +1;
  - бесплатного входа +0.5;
  - родного города пользователя +0.5, тогда как другие города теряют до 1.5 за расстояние (1 за 100 км);
  - более позднего начала, которое отнимает до 1.

  Чат сортирует по этой оценке. Если лучший результат запроса всё равно набирает меньше 3, карточка говорит, что точного совпадения нет, и показывает, что ещё будет. Пул сортирует события-кандидаты по той же оценке с чек-ином и целями и берёт лучшее плюс одно случайное из следующих четырёх, чтобы пул оставался разнообразным.
- **LLM** только заполняет действие. Она не видит афишу и не ранжирует её.

## Последствия
Загрузка делает около 16 запросов к Timepad на регион за ночь вместо 1, это по-прежнему немного. 7 дней афиши для многих городов увеличивают таблицу, а старые строки по-прежнему удаляются через 2 дня после окончания. Основы слов дают грубое совпадение («джаз» находит «Джазовый вечер», но не «саксофон»). Следующие шаги: профиль интересов, выученный по прошлым выборам (журнал `events`), и отдельная подборка «Топ рядом» из крупных открытых событий. Обе будут использовать эту оценку как базовую.
