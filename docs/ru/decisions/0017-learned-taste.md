# 0017. Профиль вкусов, выученный по действиям с квестами

[English](../../decisions/0017-learned-taste.md) · Русский

## Контекст
ADR 0015 ранжирует события по запросу, чек-ину и целям. Владелец (2026-10-23) хочет более сильную персональную рекомендацию: помощник должен предлагать то, чем интересуется пользователь, судя по его прошлым выборам. Каждый квест, который пользователь взял, выполнил или заменил, уже хранится вместе с категорией, а для событий и с названием.

## Решение
- **Источник.** Квесты пользователя за последние 60 дней, которые были взяты, выполнены или заменены (`quests.day_quests`). Только предложенные квесты ничего не говорят и в расчёт не входят. Ничего нового не хранится и ничего не покидает базу: профиль считается по запросу из строк, которые у пользователя уже есть.
- **Веса.** Выполненный квест даёт +3, взятый +1. Замена даёт -2.5, если причина «не хочу» (`dont_want`), -0.5 для «нет времени» (`no_time`) и 0 для «не могу» (`cant`), которое о вкусе ничего не говорит. Каждый сигнал теряет половину веса за 30 дней.
- **Профиль.** По каждой категории квестов взвешенная сумма сжимается в (-1, 1) формулой `v / (|v| + 4)`, поэтому несколько сигналов дают скромный эффект, а доля никогда не доходит до 1. Для квестов-событий то же считается по основам слов названия (первые 4 буквы слов), поэтому выполненный «Джазовый вечер» поднимает потом «Вечер джаза».
- **Применение.** К оценке интереса из ADR 0015 добавляется 2 × доля категории и до ±2 за любимые или нелюбимые основы названия. Это действует на квесты-события в пуле и на поиск событий помощником. Слово, которое пользователь назвал сам (×3), по-прежнему сильнее выученного вкуса.
- **Не применяется.** Блок «Топ рядом» (ADR 0016) намеренно без вкусов. Ранжирование квестов из каталога здесь не меняется.
- **Приватность.** Текст чек-ина не читается. Новых персональных данных не собирается и не пишется в логи; профиль не уходит в LLM.

## Последствия
У нового пользователя сигналов нет, профиль пуст, и ранжирование работает как в ADR 0015. Тот, кто выполняет квесты одного вида, будет видеть их чаще; насыщение и затухание ограничивают этот эффект, а явный запрос всегда важнее. Профиль пересчитывается при каждом чек-ине и поиске событий, это один запрос по индексу за максимум 60 дней квестов одного пользователя. Следующий шаг: интересы, которые пользователь укажет сам в профиле (свободные теги), они пойдут в ту же оценку.
