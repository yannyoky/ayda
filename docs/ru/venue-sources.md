# Источники заведений: бары, кафе и рестораны (issue #121)

[English](../venue-sources.md) · Русский

Ассистент M5 («Айда, организуй», #124) предлагает 3-5 мест для встречи. Здесь сравнивается, откуда можно брать места и что о них можно показать. Выбор зафиксирован в ADR 0011.

Дата исследования: 2026-10-22. Облачное окружение, в котором проводилось исследование, не имеет доступа к российским хостам (страницы документации 2GIS и Яндекса не открылись), поэтому факты ниже взяты из поисковой выдачи и из того, что провайдеры публикуют в других местах, а не из живых запросов и не со страниц официальных условий. Пункты, которые нужно сверить с официальной страницей, помечены **проверить**; живой проверкой загрузчика OpenStreetMap станет первый запуск на российском VPS.

## Что нам нужно от источника

- Заведения нужного вида (бар, паб, кафе, ресторан) рядом с городом, в любом городе России (Ayda не привязана к одному городу).
- Бесплатный доступ и условия, которые позволяют хранить снимок заведения внутри кооп-квеста и показывать его участникам.
- Название, адрес, координаты и, если есть, часы работы, кухня, сайт. Отзывы, рейтинг и средний чек желательны, но не обязательны.
- Персональные данные не покидают Ayda: запрос содержит город или район, но не пользователя.
- Только бесплатное (правило проекта). Без парсинга.

## Кандидаты

|---|---|---|---|---|
| **OpenStreetMap** через Overpass API (теги `amenity=restaurant\|cafe\|bar\|pub\|fast_food`) | Все города России; плотно в больших городах, местами пусто в малых и в часах работы | название, части адреса, координаты, `cuisine`, `opening_hours`, `website`, `phone`, часто `outdoor_seating`. **Нет отзывов, рейтинга и среднего чека** | ODbL: бесплатно, в том числе коммерчески, с указанием «© участники OpenStreetMap». ## Рекомендация

1. Базовый список из **OpenStreetMap**: ежемесячный запрос Overpass по каждому городу, где есть пользователи (радиус вокруг центра города), результат хранится в таблице `venues` модуля `events`: id в OSM, название, вид, адрес, координаты, `cuisine`, `opening_hours`, `website`. Код выбирает 3-5 кандидатов (вид, расстояние, часы работы в запланированное время, непустое название); LLM только формулирует карточку.
2. Для отзывов и среднего чека в карточке места есть **ссылки на 2ГИС и Яндекс Карты**, собранные из названия места и города (ссылки на поиск, без API и без хранения их данных): пользователь открывает место там. Шаблоны адресов проверяются при создании карточки в #124 (**проверить**).
3. На карточке показывать «© участники OpenStreetMap» (условие ODbL) и передавать название приложения в User-Agent каждого запроса к Overpass.
4. Позже собирать свои оценки после встреч (небольшое продолжение, не входит в первый срез M5).

## Чем это обходится

- В карточках нет рейтинга и среднего чека. Ссылка на приложение карт отвечает на это одним нажатием, а квест продолжает работать без сети по сохранённому снимку.
- Пробелы OSM в малых городах: ассистент предлагает меньше 3 мест и говорит об этом либо предлагает онлайн-сессию.
- Overpass может быть медленным или ограничить нас: загрузчик повторяет запрос с задержкой, пробует второй публичный экземпляр и сохраняет прошлый снимок, если оба недоступны.
- В OSM есть часы работы, но нет временного закрытия (ремонт, «временно не работает» в Яндекс Картах). Карточки пишут «открыто по графику», а не просто «открыто». Места, которые сама карта отмечает закрытыми (`opening_hours=off|closed`, `disused:*`, `was:*` и похожие префиксы жизненного цикла), пропускаются при загрузке. На каждой карточке места есть кнопка «Не работает»: место сразу пропадает из подборок этого пользователя, а у всех остальных, когда о нём сообщили двое; отметка живёт 30 дней, потом место возвращается (`events.venue_reports`, `POST /venues/{venue_id}/closed`).
